Secrets & configuration (recommended practices)\n\n- Do NOT store API keys, tokens, or secrets in source control.\n- For local development, use config/servers.yaml (kept out of VCS) or environment variables.\n- Example environment variables to set for production deployments:\n  - FOOD_API_KEY\n  - INSTAMART_API_KEY\n  - DINEOUT_API_KEY\n  - ORCH_PID_FILE (optional) — path where the orchestrator writes its PID\n\nLoading secrets in production:\n- Provision a servers.yaml at deploy time with secrets injected from your CI/CD secret store or use a secrets manager (AWS Secrets Manager, Vault, etc.).\n- Alternatively, set environment variables in the host (systemd unit, container env, or platform secret manager) and write a small wrapper to render servers.yaml from env vars.\n\nDevelopment notes:\n- The included MCPClient returns mocked responses when a server URL or API key is missing; this makes it safe to run locally without credentials.\n- When adding real keys, ensure that config/servers.yaml is excluded from commits (add to .gitignore) and rotate keys if accidentally leaked.\n
